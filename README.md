# Git Local

Self-hosted Git server for Arch Linux, running **Forgejo** (or **Gitea**) as a
per-user systemd service. All data (SQLite database, repositories, LFS objects,
logs and backups) lives on an external drive mounted at `<root>`, and nginx
serves the web interface at `http://git.local`. Git over SSH uses the built-in
SSH server of the Git server, on port 2222.

```
<root>/git.local/
├── config/
│   ├── config.ini        # generated by `make install` (contains secrets, chmod 600)
│   └── flavor            # "forgejo" or "gitea", read by the dump script
├── data/
│   ├── git-local.db      # SQLite database
│   ├── ssh/              # SSH host key of the built-in SSH server
│   ├── lfs/              # Git LFS objects
│   └── repositories/     # Git repositories
├── log/                  # server logs
└── backup/               # dumps made by the daily timer (newest 7 are kept)
```

## Requirements

- Arch Linux with `sudo` configured for your user.
- **The data root (`<root>`)**: the mount point of the drive that holds the data. You choose it
  during `make install`. There is no default, because every machine has its own disk layout. The installer creates `git.local/` inside it.
  It must be mounted, and it must have an entry in `/etc/fstab`. Set `GIT_LOCAL_ROOT` to skip the
  question (for example `GIT_LOCAL_ROOT=/mnt/data make install`). Other commands (`status`, `dump`, `uninstall`) read the root recorded by the installer; set `GIT_LOCAL_ROOT` to override it.
- The external drive mounted at `<root>` by `/etc/fstab`. Example entry for
  the current drive (exFAT, owned by `boss`):

  ```
  UUID=93E4-3F3A <root> exfat uid=boss,gid=boss,dmask=007,fmask=007,nofail,x-gvfs-show 0 0
  ```

  `nofail` lets the system boot without the drive. The installer checks for this
  line and refuses to start the server without it.
- A host alias `local` in `~/.ssh/config` (see [SSH access](#ssh-access)). The
  installer adds `Port 2222` to it if the alias exists.
- **Packages, installed by you.** The installer never runs `pacman -S`. It checks
  the packages below first and stops with the command to install any that are
  missing:
  - Both: `unzip`, `nginx`, `avahi`, `python3`
  - Forgejo: `forgejo`, `forgejo-cli`
  - Gitea: `gitea`, `gitea-runner`

  ```sh
  sudo pacman -S --needed unzip nginx avahi python forgejo forgejo-cli
  ```

  Use `gitea gitea-runner` instead for Gitea. The package `python` provides
  `python3`.

The dump script is copied to `<root>/git.local/bin/dump.py` by `make install`,
so the daily dump does not depend on this project folder.

## Installation

1. Plug in the external drive and confirm it is mounted:

   ```sh
   findmnt <root>
   ```

2. If `<root>` is not in `/etc/fstab`, add the line from
   [Requirements](#requirements) and reload systemd:

   ```sh
   sudo systemctl daemon-reload
   ```

3. Authenticate `sudo` once in the terminal. The installer uses `sudo` for
   `/etc`, nginx and linger, and a cached credential avoids repeated prompts:

   ```sh
   sudo -v
   ```

4. Run the installer from the project directory:

   ```sh
   cd ~/git.local
   make install
   ```

   The installer asks which server to use:

   ```
   Select the Git server to install:
     [1] Forgejo [Default]
     [2] Gitea
   ```

   Press Enter for Forgejo. Then it asks for the first administrator:

   ```
   Administrator username: <your username>
   Administrator email: <your email>
   ```

   The account is created from the terminal, so the web setup page is not used.
   The random password is printed once. You must change it at the first sign-in.

   The installer then:

   - checks the required packages (see [Requirements](#requirements)) and stops if
     any is missing, without changing anything;
   - creates the directories under `<root>/git.local`;
   - generates `config/config.ini` with new secrets (see [Configuration](#configuration));
   - if the database has no users and the setup was not finished, moves the old
     `config.ini` and database into `backup/pre-config-<stamp>/` and creates a new
     database. If there are users, it stops and changes nothing;
   - copies `src/etc/` to `/etc/`, backing up any file it replaces;
   - installs the user units into `~/.config/systemd/user/`;
   - disables the old `gitea.service` user unit if it exists, because it uses
     port 3000 as well;
   - removes the old Gitea key from `~/.ssh/authorized_keys`, backing it up first;
   - sets `Port 2222` for the `local` host in `~/.ssh/config`, backing it up first;
   - enables linger for your user, so services start at boot without a login;
   - tests the nginx configuration and reloads nginx;
   - runs the database migrations and creates the administrator;
   - enables the daily dump timer and starts `git-local.service`.

   Every backup has the suffix `.bak-MM-DD-YYYY_HH-MM-SS`, for example
   `/etc/nginx/nginx.conf.bak-10-20-2026_14-30-00`.

5. Add `git.local` to `/etc/hosts` on this computer. The installer checks for it at
   the start and stops, without changing anything, if it is missing. Other computers
   do not need this: the installer announces the name on the network (see
   [Network access](#network-access-other-computers-and-phones)). Use the address of this
   computer (for example `192.168.0.2`):

   ```
   192.168.0.2 git.local
   ```

6. Open `http://git.local`, sign in with the administrator account, and change the
   password when asked.

7. Add your SSH public key in the web interface: **Settings → SSH / GPG Keys →
   Add Key**. Only then can you push and pull over SSH.

## Configuration

The server reads `<root>/git.local/config/config.ini`. The installer writes:

| Section        | Key                                     | Value                                      |
|----------------|-----------------------------------------|--------------------------------------------|
| top level      | `RUN_USER`, `WORK_PATH`                 | `boss`, `<root>/git.local`               |
| `[server]`     | `HTTP_ADDR`, `HTTP_PORT`                | `127.0.0.1`, `3000` (only nginx can reach it) |
| `[server]`     | `ROOT_URL`, `DOMAIN`                    | `http://<LAN address>:8080/`, `git.local` (links use the IP so phones work) |
| `[server]`     | `APP_DATA_PATH`                         | `<root>/git.local/data`                  |
| `[server]`     | `LFS_START_SERVER`                      | `true`                                     |
| `[server]`     | `START_SSH_SERVER`, `SSH_LISTEN_PORT`   | `true`, `2222` (port the SSH server listens on) |
| `[server]`     | `SSH_DOMAIN`, `SSH_PORT`                | `local`, `22` (what clone URLs show: `git@local:<owner>/<repo>.git`) |
| `[server]`     | `SSH_USER`, `BUILTIN_SSH_SERVER_USER`   | `git` (the login name in clone URLs; no system user needed) |
| `[server]`     | `SSH_CREATE_AUTHORIZED_KEYS_FILE`       | `false` (never touches `~/.ssh/authorized_keys`) |
| `[database]`   | `DB_TYPE`, `PATH`                       | `sqlite3`, `<root>/git.local/data/git-local.db` |
| `[repository]` | `ROOT`                                  | `<root>/git.local/data/repositories`     |
| `[log]`        | `MODE`, `ROOT_PATH`                     | `console` (journal), `<root>/git.local/log` |
| `[security]`   | `INSTALL_LOCK`                          | `true` (the web setup page is disabled)    |
| `[security]`   | `PASSWORD_HASH_ALGO`                    | `argon2`                                   |
| `[service]`    | `DISABLE_REGISTRATION`                  | `true` (only the administrator creates accounts) |
| `[service]`    | `REQUIRE_SIGNIN_VIEW`                   | `true` (nobody on the network sees repositories without an account) |
| `[openid]`     | `ENABLE_OPENID_SIGNIN`, `ENABLE_OPENID_SIGNUP` | `false`                             |
| `[session]`    | `PROVIDER`                              | `file`                                     |

The secrets (`SECRET_KEY`, `INTERNAL_TOKEN`, `[oauth2] JWT_SECRET`,
`[server] LFS_JWT_SECRET`) are generated by `forgejo generate secret` at install
time. Keep the file private; it is readable only by your user.

To change a setting, edit the file and restart the service:

```sh
systemctl --user restart git-local.service
```

`make install` keeps an existing `config.ini` once the setup is finished, so
editing it by hand is the way to change settings later.

### nginx

`src/etc/nginx/conf.d/git-local.conf` proxies port 80 for `git.local` to
`127.0.0.1:3000`. `src/etc/nginx/conf.d/fileserver.conf` serves
`/home/boss/Público` on port 80 for any other host name (`default_server`).

## Network access (other computers and phones)

The web interface listens only on `127.0.0.1:3000`, on purpose. nginx listens on
port 80 and forwards requests for the name `git.local` to it. Use the name, not the
IP and not port 3000:

- `http://git.local/` opens Forgejo.
- `http://192.168.0.2/` opens the file server (`/home/boss/Público`). This is
  expected: nginx has no name to match, so it uses the default site.
- `http://192.168.0.2:3000/` does not open. Port 3000 is only for nginx on this
  computer.

### How the name is found

nginx cannot resolve names: a computer must find the IP of `git.local` first. The
installer announces `git.local` on the local network with mDNS (Avahi), a service
`git-local-mdns.service` runs `avahi-publish`. Computers that understand `.local`
names resolve it without any setup:

| Device | Needs setup? |
|---|---|
| Linux with `nss-mdns` (`/etc/nsswitch.conf` has `mdns` in `hosts`) | No |
| macOS, iPhone, iPad | No |
| Windows 10 / 11 | No |
| Android | Use `http://<LAN address>:8080/` (see below) |

This computer uses `/etc/hosts` for `git.local` (its `nsswitch.conf` does not use
mDNS), so the installer still checks that line.

Test from another computer:

```sh
getent hosts git.local        # Linux: should print 192.168.0.2
curl -I http://git.local/     # should answer HTTP 200
```

### Phones (and any device without name resolution)

Android cannot resolve `.local` names, and a phone cannot edit a hosts file. Use the
address and the phone port instead, on the same Wi-Fi:

```
http://192.168.0.2:8080/
```

This port belongs to nginx, which forwards it to Forgejo. Port 80 on the same
address is the file server, and port 3000 is local to this computer. The
installer sets `ROOT_URL` to this address, so the links on the page also work from
the phone. Opening `http://git.local/` still works on computers, and their links
also use the address.

Traffic on this port is plain HTTP, so use it only on a network you trust.

### Firewall

The installer does **not** change firewall rules. It prints a warning when ports
**8080** (phones) and **2222** (Git over SSH) must be opened for your local
network. Open them with the firewall you use. The examples below use the local
subnet `192.168.0.0/24`; change it to yours.

Without these rules, the phone loads for a while and then times out, and other
computers cannot clone over SSH, even though the server is running.

#### iptables

This computer's default ruleset is `/etc/iptables/iptables.rules`. It accepts only
ports 80 and 443 from the network and drops the rest. Add these two lines **after**
the line `-A INPUT -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT` and
**before** the drop rules:

```
-A INPUT -s 192.168.0.0/24 -p tcp --dport 8080 -m conntrack --ctstate NEW -j ACCEPT
-A INPUT -s 192.168.0.0/24 -p tcp --dport 2222 -m conntrack --ctstate NEW -j ACCEPT
```

Check the file, then reload iptables:

```sh
sudo iptables-restore --test < /etc/iptables/iptables.rules
sudo systemctl restart iptables
```

To test without saving (lost on reboot), insert the rules at the top of the chain:

```sh
sudo iptables -I INPUT -s 192.168.0.0/24 -p tcp --dport 8080 -j ACCEPT
sudo iptables -I INPUT -s 192.168.0.0/24 -p tcp --dport 2222 -j ACCEPT
```

Check the order with `sudo iptables -S INPUT`: the two ACCEPT rules must come
before any DROP or REJECT rule that matches these ports.

#### nftables

In `/etc/nftables.conf`, inside `chain input`, add this line **before** the final
`counter` and `reject` rules (for example, right after `tcp dport ssh accept`):

```
tcp dport { 8080, 2222 } ip saddr 192.168.0.0/24 ct state new accept
```

Check the file and reload:

```sh
sudo nft -c -f /etc/nftables.conf
sudo systemctl restart nftables
```

#### ufw

If you use ufw instead:

```sh
sudo ufw allow from 192.168.0.0/24 to any port 8080,2222 proto tcp
```

### Fixed IP

The address of this computer is used by the phone address, by the `git.local`
announcement and by Forgejo's links. `make install` checks how the address is
assigned:

- **Static** (fixed): the installer announces it and continues.
- **DHCP** (may change): the installer shows a warning and continues. A DHCP
  address changes when the router gives a new one, and then phones and other
  computers stop working until you run `make install` again.

The installer reads the NetworkManager profile of the device and the kernel's
`dynamic` flag. To fix the address:

- on this computer, set the connection to a manual IPv4 address (NetworkManager:
  `nmcli connection modify <profile> ipv4.method manual ipv4.addresses <ip>/24 ipv4.gateway <gateway>`,
  then reactivate the connection), or
- reserve the address for this computer in the router's DHCP settings.

Then run `make install` again, so the address is checked and the settings are updated.

### Security

Port 80 is plain HTTP, so passwords travel unencrypted on the local network. Use
this only on a network you trust. For access from outside, use a VPN.

## SSH access

Git over SSH uses the built-in SSH server of Forgejo on port **2222**. The
system `sshd` and `~/.ssh/authorized_keys` are not used, so there is no conflict
with other keys on the machine.

The web interface shows clone URLs in the short form `git@local:<owner>/<repo>.git`.
The `local` host alias in `~/.ssh/config` sets the real port (2222), so the URL
works without typing the port:

```
Host local
    Port 2222
    HostName git.local
    User git
    IdentityFile ~/.ssh/local_williamcanin
    IdentitiesOnly yes
```

```sh
git clone local:<owner>/<repo>.git
ssh -T local
```

The first connection asks you to accept the server fingerprint. Before your key
is added in the web interface, `ssh -T local` returns `Permission denied
(publickey)`. That means the SSH server is running.

## Services

| Unit                       | What it does                                              |
|----------------------------|-----------------------------------------------------------|
| `git-local.service`        | Runs `forgejo web` or `gitea web` with the config above.  |
| `git-local-dump.timer`     | Starts the dump every day at 03:30.                       |
| `git-local-dump.service`   | Runs `<root>/git.local/bin/dump.py` once (triggered by the timer). |

Both services wait up to 60 seconds for `<root>` to be mounted before they
start, because user units cannot depend on the system mount unit.

Useful commands:

```sh
systemctl --user status git-local.service
systemctl --user list-timers git-local-dump.timer
journalctl --user -u git-local.service -f
journalctl --user -u git-local-dump.service
```

Linger is enabled by the installer. Check it with:

```sh
loginctl show-user "$USER" --property=Linger
```

## Backups

The daily dump protects the data against damage to the SQLite database and the
drive. It is made with the official `gitea dump` or `forgejo dump` command
and includes the database, repositories, LFS objects, attachments, logs and
config.

What `<root>/git.local/bin/dump.py` does:

1. Stops `git-local.service`, so the SQLite database is not written while it is
   copied. The server is unavailable for the duration of the dump.
2. Writes `<root>/git.local/backup/git-local-MM-DD-YYYY_HH-MM-SS.zip`.
3. Checks the archive with `unzip -t`. A failed dump or check removes the
   partial file and returns an error.
4. Keeps the 7 newest dumps and deletes older ones.
5. Starts `git-local.service` again if it was running before, even if the dump
   failed.

Run a dump now:

```sh
make dump
```

Check the timer and the last run:

```sh
systemctl --user list-timers git-local-dump.timer
journalctl --user -u git-local-dump.service -n 50
```

The timer uses `Persistent=true`, so a dump missed while the computer was off
runs at the next boot.

### Keep a copy off the drive

The dumps are stored on the same drive as the data. If the drive fails, both are
lost. Copy the newest dump to another disk, a cloud folder, or another machine
regularly. The script does not do this for you.

### Restoring a dump

Restore is manual. Read the upstream restore guide for your server version
(Gitea: <https://docs.gitea.com/administration/backup-and-restore>;
Forgejo: <https://forgejo.org/docs/latest/admin/>). In short:

1. Stop the service: `systemctl --user stop git-local.service`.
2. Extract the archive into a new empty directory, not into `<root>`.
3. Restore the database, repositories, LFS objects and config from the
   extracted files, following the guide.
4. Start the service: `systemctl --user start git-local.service`.

Test a restore on a copy before you need it.

## Filesystem for the external drive

The drive is a USB HDD (Seagate ST500LM012, 465.8 GB) with an exFAT partition
for `<root>`. For the goal of **Linux and Windows access without NTFS and
with protection against corruption**, the tradeoffs are:

| Filesystem | Linux | Windows | Journal (crash safety) | Notes                                                      |
|------------|-------|---------|------------------------|------------------------------------------------------------|
| exFAT      | r/w   | r/w     | No                     | Current choice. Cross-platform, but no journal. No symlinks, no Unix permissions. |
| FAT32      | r/w   | r/w     | No                     | Worse than exFAT: 4 GB file size limit, which dumps can exceed. |
| UDF        | r/w   | r only  | No                     | Writing from Windows is not reliable.                      |
| ext4       | r/w   | no (third-party drivers only) | **Yes**       | Best protection on Linux (journal and `fsck`). Not usable from Windows without drivers. |

No filesystem other than NTFS combines a journal with full read/write on both
systems. Btrfs, ZFS, APFS and ReFS each lack a reliable driver on the other
system.

**Recommendation:**

- If Windows does not need to write to this drive, reformat it as **ext4**.
  This is the safest choice for the Git data and the dumps.
- If Windows must read and write the drive, use **two partitions**: an ext4
  partition for `<root>/git.local`, and a small exFAT partition for files
  shared with Windows.
- If you keep exFAT for everything, always unmount before unplugging the drive,
  run dumps (`make dump`), and check the filesystem with `fsck.exfat -n` (from
  the `exfatprogs` package) when something looks wrong.

Reformatting erases the drive. Back up the data first. This project does not
reformat or repartition the drive.

## Troubleshooting

- **`http://192.168.0.2/` shows a file listing**: expected. Use `http://git.local/`
  (see [Network access](#network-access-other-computers-and-phones)).
- **`http://192.168.0.2:3000/` does not open**: expected. Port 3000 is only for
  nginx on this computer.
- **`http://git.local/` does not open on another computer**: run `getent hosts git.local`.
  If it prints nothing, the computer does not use mDNS (see [How the name is found](#how-the-name-is-found)),
  or mDNS is blocked on the network (UDP 5353). If it resolves but `curl` times out,
  a firewall on this computer may block port 80 (`sudo ufw status` or `sudo nft list ruleset`).
- **`git.local` resolves to another address on the network**: another computer is
  announcing the same name. Check with `avahi-resolve -n git.local` and turn off the other announcement.
- **Phone loads and then times out, but `http://<IP>/` opens**: the firewall blocks
  port 8080. Add the rule (see [Firewall](#firewall)).
- **Other computers cannot clone over SSH (port 2222)**: the same firewall rule.
- **Installer warns that the address comes from DHCP**: fix the address (see
  [Fixed IP](#fixed-ip)) and run `make install` again.
- **Phone does not open the server**: use `http://<LAN address>:8080/` (see
  [Phones](#phones-and-any-device-without-name-resolution)). The address must be fixed, and the phone must be on the same network.

- **`<root> is not mounted`**: mount the drive (`sudo mount <root>`) or fix
  the `/etc/fstab` entry. The installer and the dump refuse to run without it.
- **`/etc/fstab has no entry for <root>`**: add the line from
  [Requirements](#requirements), run `sudo systemctl daemon-reload`, then run
  `make install` again. The service is not started until the line exists.
- **`The database already has N user(s)`**: the installer does not replace a
  database that has accounts. Finish the setup manually or move the database
  out of the way yourself.
- **Port 3000 already in use**: another Gitea or Forgejo is running. Stop it with
  `systemctl --user disable --now gitea.service`, or change `HTTP_PORT` in
  `config.ini` and `src/etc/nginx/conf.d/git-local.conf`.
- **`ssh -T local` fails with a connection error**: check that the service is
  running and that port 2222 is listening (`ss -ltnp | grep 2222`).
- **`Permission denied (publickey)`**: add your public key in the web interface
  (see [Installation](#installation), step 7).
- **nginx test failed**: run `sudo nginx -t` to see the error. The installer does
  not reload nginx in that case. The previous file is in the `.bak-...` backup.
- **`git-local.service` fails at start**: run
  `journalctl --user -u git-local.service -n 100`. A common cause is the drive
  not mounted in time. The unit waits up to 60 seconds.
- **Repository permissions on exFAT**: exFAT has no Unix permissions. The mount
  options (`uid=boss,gid=boss`) make the files owned by `boss`, which is what the
  server needs.

## Uninstall

```sh
make uninstall
```

After a confirmation prompt, it:

1. Stops and disables `git-local.service`, `git-local-dump.service` and
   `git-local-dump.timer`, and removes their files from `~/.config/systemd/user/`.
2. Restores each `/etc` file from the newest `.bak-…` backup made by the
   installer (or removes the file when the installer created it). It then tests
   and reloads nginx.
3. Removes `<root>/git.local/bin/dump.py`.
4. Disables linger for your user, so services no longer start at boot without a
   login.

It keeps:

- everything under `<root>/git.local`: `data/` (repositories and database),
  `config/` (including the secrets), `log/` and `backup/` (including all dumps and
  installer backups);
- the installed packages;
- `~/.ssh/config` (including the `Port 2222` line) and `~/.ssh/authorized_keys`;
- the state of the nginx service.

To remove the data too, delete `<root>/git.local` by hand after you have a
copy of the newest dump.
