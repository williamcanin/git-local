# Git Local

Self-hosted Git server for Arch Linux, running **Forgejo** (or **Gitea**) as a
per-user systemd service. All data (SQLite database, repositories, LFS objects,
logs and backups) lives on an external drive mounted at `/seagate`, and nginx
serves the web interface at `http://git.local`. Git over SSH uses the built-in
SSH server of the Git server, on port 2222.

```
/seagate/git.local/
├── config/
│   ├── config.ini        # generated by `make install` (contains secrets, chmod 600)
│   └── flavor            # "forgejo" or "gitea", read by the dump script
├── data/
│   ├── git-local.db      # SQLite database
│   ├── ssh/              # SSH host key of the built-in SSH server
│   ├── lfs/              # Git LFS objects
│   └── repositories/     # Git repositories
├── log/                  # server logs
└── backup/               # dumps made by the daily timer (newest 7 are kept)
```

## Requirements

- Arch Linux with `sudo` configured for your user.
- The external drive mounted at `/seagate` by `/etc/fstab`. Example entry for
  the current drive (exFAT, owned by `boss`):

  ```
  UUID=93E4-3F3A /seagate exfat uid=boss,gid=boss,dmask=007,fmask=007,nofail,x-gvfs-show 0 0
  ```

  `nofail` lets the system boot without the drive. The installer checks for this
  line and refuses to start the server without it.
- The project cloned or copied to `~/git.local`. The dump timer uses the path
  `%h/git.local/.tools/dump.sh`, so keep the project there or edit
  `src/.config/systemd/user/git-local-dump.service`.
- A host alias `local` in `~/.ssh/config` (see [SSH access](#ssh-access)). The
  installer adds `Port 2222` to it if the alias exists.
- Packages from the `extra` repository (installed automatically):
  - Forgejo: `forgejo`, `forgejo-cli`
  - Gitea: `gitea`, `gitea-runner`
  - Both: `unzip`. `python3` is used to count users in the database.

## Installation

1. Plug in the external drive and confirm it is mounted:

   ```sh
   findmnt /seagate
   ```

2. If `/seagate` is not in `/etc/fstab`, add the line from
   [Requirements](#requirements) and reload systemd:

   ```sh
   sudo systemctl daemon-reload
   ```

3. Authenticate `sudo` once in the terminal. The installer uses `sudo` for
   `/etc`, nginx and linger, and a cached credential avoids repeated prompts:

   ```sh
   sudo -v
   ```

4. Run the installer from the project directory:

   ```sh
   cd ~/git.local
   make install
   ```

   The installer asks which server to use:

   ```
   Select the Git server to install:
     [1] Forgejo [Default]
     [2] Gitea
   ```

   Press Enter for Forgejo. Then it asks for the first administrator:

   ```
   Administrator username: <your username>
   Administrator email: <your email>
   ```

   The account is created from the terminal, so the web setup page is not used.
   The random password is printed once. You must change it at the first sign-in.

   The installer then:

   - installs the packages for the chosen server, plus `unzip`;
   - creates the directories under `/seagate/git.local`;
   - generates `config/config.ini` with new secrets (see [Configuration](#configuration));
   - if the database has no users and the setup was not finished, moves the old
     `config.ini` and database into `backup/pre-config-<stamp>/` and creates a new
     database. If there are users, it stops and changes nothing;
   - copies `src/etc/` to `/etc/`, backing up any file it replaces;
   - installs the user units into `~/.config/systemd/user/`;
   - disables the old `gitea.service` user unit if it exists, because it uses
     port 3000 as well;
   - removes the old Gitea key from `~/.ssh/authorized_keys`, backing it up first;
   - sets `Port 2222` for the `local` host in `~/.ssh/config`, backing it up first;
   - enables linger for your user, so services start at boot without a login;
   - tests the nginx configuration and reloads nginx;
   - runs the database migrations and creates the administrator;
   - enables the daily dump timer and starts `git-local.service`.

   Every backup has the suffix `.bak-MM-DD-YYYY_HH-MM-SS`, for example
   `/etc/nginx/nginx.conf.bak-10-20-2026_14-30-00`.

5. Make `git.local` resolve to this computer if your network does not already
   do it, for example with an `/etc/hosts` entry:

   ```
   192.168.0.2 git.local
   ```

6. Open `http://git.local`, sign in with the administrator account, and change the
   password when asked.

7. Add your SSH public key in the web interface: **Settings → SSH / GPG Keys →
   Add Key**. Only then can you push and pull over SSH.

## Configuration

The server reads `/seagate/git.local/config/config.ini`. The installer writes:

| Section        | Key                                     | Value                                      |
|----------------|-----------------------------------------|--------------------------------------------|
| top level      | `RUN_USER`, `WORK_PATH`                 | `boss`, `/seagate/git.local`               |
| `[server]`     | `HTTP_ADDR`, `HTTP_PORT`                | `127.0.0.1`, `3000` (only nginx can reach it) |
| `[server]`     | `ROOT_URL`, `DOMAIN`                    | `http://git.local/`, `git.local`           |
| `[server]`     | `APP_DATA_PATH`                         | `/seagate/git.local/data`                  |
| `[server]`     | `LFS_START_SERVER`                      | `true`                                     |
| `[server]`     | `START_SSH_SERVER`, `SSH_LISTEN_PORT`, `SSH_PORT` | `true`, `2222`, `2222`           |
| `[server]`     | `SSH_USER`, `BUILTIN_SSH_SERVER_USER`   | `boss`                                     |
| `[server]`     | `SSH_CREATE_AUTHORIZED_KEYS_FILE`       | `false` (never touches `~/.ssh/authorized_keys`) |
| `[database]`   | `DB_TYPE`, `PATH`                       | `sqlite3`, `/seagate/git.local/data/git-local.db` |
| `[repository]` | `ROOT`                                  | `/seagate/git.local/data/repositories`     |
| `[log]`        | `MODE`, `ROOT_PATH`                     | `console` (journal), `/seagate/git.local/log` |
| `[security]`   | `INSTALL_LOCK`                          | `true` (the web setup page is disabled)    |
| `[security]`   | `PASSWORD_HASH_ALGO`                    | `argon2`                                   |
| `[service]`    | `DISABLE_REGISTRATION`                  | `true` (only the administrator creates accounts) |
| `[service]`    | `REQUIRE_SIGNIN_VIEW`                   | `true` (nobody on the network sees repositories without an account) |
| `[openid]`     | `ENABLE_OPENID_SIGNIN`, `ENABLE_OPENID_SIGNUP` | `false`                             |
| `[session]`    | `PROVIDER`                              | `file`                                     |

The secrets (`SECRET_KEY`, `INTERNAL_TOKEN`, `[oauth2] JWT_SECRET`,
`[server] LFS_JWT_SECRET`) are generated by `forgejo generate secret` at install
time. Keep the file private; it is readable only by your user.

To change a setting, edit the file and restart the service:

```sh
systemctl --user restart git-local.service
```

`make install` keeps an existing `config.ini` once the setup is finished, so
editing it by hand is the way to change settings later.

### nginx

`src/etc/nginx/conf.d/git-local.conf` proxies port 80 for `git.local` to
`127.0.0.1:3000`. `src/etc/nginx/conf.d/fileserver.conf` serves
`/home/boss/Público` on port 80 for any other host name (`default_server`).

## SSH access

Git over SSH uses the built-in SSH server of Forgejo on port **2222**. The
system `sshd` and `~/.ssh/authorized_keys` are not used, so there is no conflict
with other keys on the machine.

The `local` host alias in `~/.ssh/config` sets the port, so the short URL still
works:

```
Host local
    Port 2222
    HostName git.local
    User boss
    IdentityFile ~/.ssh/local_williamcanin
    IdentitiesOnly yes
```

```sh
git clone local:<owner>/<repo>.git
ssh -T local
```

The first connection asks you to accept the server fingerprint. Before your key
is added in the web interface, `ssh -T local` returns `Permission denied
(publickey)`. That means the SSH server is running.

## Services

| Unit                       | What it does                                              |
|----------------------------|-----------------------------------------------------------|
| `git-local.service`        | Runs `forgejo web` or `gitea web` with the config above.  |
| `git-local-dump.timer`     | Starts the dump every day at 03:30.                       |
| `git-local-dump.service`   | Runs `.tools/dump.sh` once (triggered by the timer).     |

Both services wait up to 60 seconds for `/seagate` to be mounted before they
start, because user units cannot depend on the system mount unit.

Useful commands:

```sh
systemctl --user status git-local.service
systemctl --user list-timers git-local-dump.timer
journalctl --user -u git-local.service -f
journalctl --user -u git-local-dump.service
```

Linger is enabled by the installer. Check it with:

```sh
loginctl show-user "$USER" --property=Linger
```

## Backups

The daily dump protects the data against damage to the SQLite database and the
drive. It is made with the official `gitea dump` or `forgejo dump` command
and includes the database, repositories, LFS objects, attachments, logs and
config.

What `.tools/dump.sh` does:

1. Stops `git-local.service`, so the SQLite database is not written while it is
   copied. The server is unavailable for the duration of the dump.
2. Writes `/seagate/git.local/backup/git-local-MM-DD-YYYY_HH-MM-SS.zip`.
3. Checks the archive with `unzip -t`. A failed dump or check removes the
   partial file and returns an error.
4. Keeps the 7 newest dumps and deletes older ones.
5. Starts `git-local.service` again if it was running before, even if the dump
   failed.

Run a dump now:

```sh
make dump
```

Check the timer and the last run:

```sh
systemctl --user list-timers git-local-dump.timer
journalctl --user -u git-local-dump.service -n 50
```

The timer uses `Persistent=true`, so a dump missed while the computer was off
runs at the next boot.

### Keep a copy off the drive

The dumps are stored on the same drive as the data. If the drive fails, both are
lost. Copy the newest dump to another disk, a cloud folder, or another machine
regularly. The script does not do this for you.

### Restoring a dump

Restore is manual. Read the upstream restore guide for your server version
(Gitea: <https://docs.gitea.com/administration/backup-and-restore>;
Forgejo: <https://forgejo.org/docs/latest/admin/>). In short:

1. Stop the service: `systemctl --user stop git-local.service`.
2. Extract the archive into a new empty directory, not into `/seagate`.
3. Restore the database, repositories, LFS objects and config from the
   extracted files, following the guide.
4. Start the service: `systemctl --user start git-local.service`.

Test a restore on a copy before you need it.

## Filesystem for the external drive

The drive is a USB HDD (Seagate ST500LM012, 465.8 GB) with an exFAT partition
for `/seagate`. For the goal of **Linux and Windows access without NTFS and
with protection against corruption**, the tradeoffs are:

| Filesystem | Linux | Windows | Journal (crash safety) | Notes                                                      |
|------------|-------|---------|------------------------|------------------------------------------------------------|
| exFAT      | r/w   | r/w     | No                     | Current choice. Cross-platform, but no journal. No symlinks, no Unix permissions. |
| FAT32      | r/w   | r/w     | No                     | Worse than exFAT: 4 GB file size limit, which dumps can exceed. |
| UDF        | r/w   | r only  | No                     | Writing from Windows is not reliable.                      |
| ext4       | r/w   | no (third-party drivers only) | **Yes**       | Best protection on Linux (journal and `fsck`). Not usable from Windows without drivers. |

No filesystem other than NTFS combines a journal with full read/write on both
systems. Btrfs, ZFS, APFS and ReFS each lack a reliable driver on the other
system.

**Recommendation:**

- If Windows does not need to write to this drive, reformat it as **ext4**.
  This is the safest choice for the Git data and the dumps.
- If Windows must read and write the drive, use **two partitions**: an ext4
  partition for `/seagate/git.local`, and a small exFAT partition for files
  shared with Windows.
- If you keep exFAT for everything, always unmount before unplugging the drive,
  run dumps (`make dump`), and check the filesystem with `fsck.exfat -n` (from
  the `exfatprogs` package) when something looks wrong.

Reformatting erases the drive. Back up the data first. This project does not
reformat or repartition the drive.

## Troubleshooting

- **`/seagate is not mounted`**: mount the drive (`sudo mount /seagate`) or fix
  the `/etc/fstab` entry. The installer and the dump refuse to run without it.
- **`/etc/fstab has no entry for /seagate`**: add the line from
  [Requirements](#requirements), run `sudo systemctl daemon-reload`, then run
  `make install` again. The service is not started until the line exists.
- **`The database already has N user(s)`**: the installer does not replace a
  database that has accounts. Finish the setup manually or move the database
  out of the way yourself.
- **Port 3000 already in use**: another Gitea or Forgejo is running. Stop it with
  `systemctl --user disable --now gitea.service`, or change `HTTP_PORT` in
  `config.ini` and `src/etc/nginx/conf.d/git-local.conf`.
- **`ssh -T local` fails with a connection error**: check that the service is
  running and that port 2222 is listening (`ss -ltnp | grep 2222`).
- **`Permission denied (publickey)`**: add your public key in the web interface
  (see [Installation](#installation), step 7).
- **nginx test failed**: run `sudo nginx -t` to see the error. The installer does
  not reload nginx in that case. The previous file is in the `.bak-...` backup.
- **`git-local.service` fails at start**: run
  `journalctl --user -u git-local.service -n 100`. A common cause is the drive
  not mounted in time. The unit waits up to 60 seconds.
- **Repository permissions on exFAT**: exFAT has no Unix permissions. The mount
  options (`uid=boss,gid=boss`) make the files owned by `boss`, which is what the
  server needs.

## Uninstall

```sh
make uninstall
```

This stops and removes `git-local.service`, `git-local-dump.service` and
`git-local-dump.timer` from `~/.config/systemd/user/`. It keeps:

- the installed packages,
- the `/etc` files (nginx) and their backups,
- everything under `/seagate/git.local`, including dumps.

Remove those manually if you no longer need them.
